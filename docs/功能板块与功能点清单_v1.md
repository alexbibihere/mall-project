## 板块一：用户板块 [M1]（5 个功能点）

### 1.1 注册/登录
- **完整功能**：手机号+验证码注册；账号密码登录 + 短信验证码登录两种方式；登录签发 JWT（含 userId、角色），有效期内免登；退出登录 Token 失效（Redis 黑名单）。
- **关键规则**：验证码 60s 有效、单手机号 1 分钟 1 条/日 10 条；密码 BCrypt 加密存储；连续 5 次失败锁定 30 分钟。
- **技术落点**：JWT 无状态认证、Redis Token 黑名单、接口级验证码防刷（Redis 计数）。

### 1.2 个人信息管理
- **完整功能**：查看/修改昵称、头像、性别、生日；头像上传走 MinIO + CDN；敏感信息（手机号）脱敏展示。
- **关键规则**：昵称唯一性校验；修改即删用户维度缓存（Cache-Aside 先更库再删缓存）。
- **技术落点**：对象存储上传直传（Presigned URL）、缓存一致性（先更 DB 再删缓存）。

### 1.3 收货地址管理
- **完整功能**：地址增删改查；省市区三级联动；默认地址唯一（设默认自动取消旧默认）；下单时从地址库选择。
- **关键规则**：单用户上限 20 条；删除为逻辑删除；下单快照保存地址冗余（防地址后续修改影响历史订单）。
- **技术落点**：订单快照设计（数据冗余防变更）。

### 1.4 用户风控
- **完整功能**：黑名单用户禁止下单/参与秒杀；秒杀限购校验（每活动每用户 1 件）；异常行为（高频请求）自动限流标记。
- **关键规则**：黑名单命中查 Redis Set，O(1)；限购记录 Lua 脚本内原子校验。
- **技术落点**：Redis Set 黑名单、Lua 原子「限购+扣减」合一、网关层风控前置。

### 1.5 会员等级
- **完整功能**：消费积分累计升级（V1~V5）；不同等级享不同优惠系数；积分随订单确认收货发放、退款回滚。
- **关键规则**：积分变更走本地消息表异步记账，可对账补偿。
- **技术落点**：本地消息表最终一致、积分账户流水（防超扣）。

## 板块二：商品板块 [M1]（6 个功能点）

### 2.1 类目管理
- **完整功能**：三级类目树（家电→电视→曲面电视）的后台维护；类目与品牌关联；前台按类目树导航；类目禁用级联隐藏商品。
- **关键规则**：删除类目前校验无子节点且无挂载商品；类目树全量缓存。
- **技术落点**：树结构缓存（Caffeine+Redis 两级）、变更时双删。

### 2.2 品牌管理
- **完整功能**：品牌增删改查、品牌与类目多对多关联、品牌 logo 上传、启用/禁用。
- **关键规则**：禁用品牌下商品不可新上架，在售不受影响。
- **技术落点**：常规 CRUD + 缓存。

### 2.3 商品 SPU/SKU 管理
- **完整功能**：SPU（标准商品）+ 多 SKU（规格组合：颜色×内存）；SKU 独立价格/库存/图片；销售属性模板（类目维度）；商品草稿→待审核→在售状态流转。
- **关键规则**：SKU 价格修改记录变更流水；在售商品不可删除只可下架。
- **技术落点**：SPU/SKU 领域建模、状态机、商品数据版本号（乐观锁防并发改）。

### 2.4 商品详情（读多写少核心场景）
- **完整功能**：详情页聚合 SPU 信息、SKU 列表、图文详情、库存可售状态；页面静态化生成 HTML 推 CDN；未静态化部分走接口。
- **关键规则**：读链路三级漏斗 Caffeine → Redis → DB；详情数据 5 分钟逻辑过期异步刷新；静态页商品变更主动失效（MQ 广播各节点删本地缓存）。
- **技术落点**：多级缓存、逻辑过期防击穿、静态化+CDN 卸载 90% 读流量、MQ 广播本地缓存失效。

### 2.5 商品上下架与缓存同步
- **完整功能**：上架：校验 SKU 完整性 → 同步 ES 索引 → 预热缓存 → 静态化；下架：反向失效缓存与索引。
- **关键规则**：上架失败任一环节回滚状态；ES 与缓存最终一致（失败进重试表）。
- **技术落点**：缓存预热、DB↔ES 同步链路（MQ 异步 + 失败重试）。

### 2.6 库存展示
- **完整功能**：详情页/列表页展示「有货/紧张/无货」三态（不展示精确数防竞对爬取）；秒杀商品展示活动倒计时与活动价。
- **关键规则**：库存状态从 Redis 读（预扣口径），不直查 DB。
- **技术落点**：读流量全部挡在缓存层。

## 板块三：搜索板块 [M2]（5 个功能点）

### 3.1 商品检索
- **完整功能**：关键词全文检索（商品名/品牌/类目/卖点）；分词采用 IK（自定义商品词库）；结果按相关度默认排序；分页返回（深分页用 search_after）。
- **关键规则**：仅检索「在售+审核通过」商品；查询超时 800ms 熔断降级为类目浏览。
- **技术落点**：ES 集群、IK 分词、search_after 深分页、查询熔断降级。

### 3.2 筛选与聚合
- **完整功能**：按品牌、价格区间、规格属性（内存/颜色）、类目多条件过滤；聚合返回各筛选项的可选项与数量（faceted search）；排序支持价格/销量/新品/评分。
- **关键规则**：聚合查询与全文查询合并为一次 ES 请求。
- **技术落点**：ES bool+aggs、多条件组合查询性能调优。

### 3.3 搜索建议
- **完整功能**：输入联想（completion suggester）；热门搜索词榜（Redis ZSet 实时统计，小时级滚动）；无结果页推荐相似商品。
- **关键规则**：热搜词榜 anti-spam（同用户同词 5 分钟去重计数）。
- **技术落点**：ES completion、Redis ZSet 热榜、防刷计数。

### 3.4 商品数据同步（DB → ES）
- **完整功能**：商品上架/改价/改库存后异步同步 ES；链路：业务落库 → 发 MQ → 同步服务消费更新索引；另备 Canal 订阅 binlog 兜底（防漏发消息）；同步失败进重试队列，超限告警人工介入。
- **关键规则**：以 binlog 顺序为准防乱序；同步带版本号防旧数据覆盖新数据。
- **技术落点**：MQ 异步同步 vs Canal 订阅 binlog 双方案对比（面试高频）、乱序与幂等处理。

### 3.5 索引生命周期
- **完整功能**：商品索引按月滚动（index-2026.09）；索引模板统一 mapping；别名切换实现零停机重建索引；全量重建任务（XXL-Job 触发，分页拉取 bulk 写入）。
- **关键规则**：重建期间双写新旧索引，校验文档数一致后切别名。
- **技术落点**：索引模板+别名滚动、bulk 批量写入、零停机重建。

## 板块四：购物车板块 [M1]（3 个功能点）

### 4.1 购物车操作
- **完整功能**：加购（选 SKU+数量）、修改数量、删除、勾选/取消勾选、清空失效商品；登录与未登录（临时车）均可用，登录后临时车自动合并。
- **关键规则**：加购上限 120 种 SKU；购物车不落库，全量存 Redis Hash（field=skuId, value=数量+勾选态+加购时间）；商品改价/下架时购物车条目标记「价格已变/已失效」。
- **技术落点**：Redis Hash 购物车模型、登录合并策略（数量取大者）、不落库扛高并发写。

### 4.2 购物车结算预览
- **完整功能**：勾选商品实时试算：单价×数量汇总、可用优惠券列表、满减命中提示、运费预估、应付总额；库存校验（缺货标红不可结算）。
- **关键规则**：试算只读不锁库存；营销试算调用营销中心接口（弱依赖，超时降级为无优惠金额）。
- **技术落点**：价格试算服务、弱依赖降级（Sentinel 熔断兜底价）。

### 4.3 购物车风控
- **完整功能**：加购接口限流（单用户 10 次/秒）；黄牛批量加购识别（同 IP 高频告警）。
- **关键规则**：与用户风控黑名单联动。
- **技术落点**：用户级限流（Redis+Lua 滑动窗口）。

## 板块五：交易板块（订单中心）[M1 起步/M3 分库分表]（7 个功能点）

### 5.1 订单创建（核心链路）
- **完整功能**：入参（地址 id、SKU+数量列表、优惠券 id）→ 校验（商品状态/库存/限购/风控）→ 计算价格（优惠分摊到 SKU 行）→ Redis 预扣库存 → 生成订单号 → 本地消息表写订单事件 → 发 RocketMQ 事务消息 → 异步落库 → 返回「下单受理中」；前端轮询/推送订单状态。
- **关键规则**：主链路只做「校验+预扣+发消息」三件事，落库全异步；优惠券核销、积分扣减、清购物车全在消费端；任何一步失败预扣库存回补。
- **技术落点**：异步化下单、RocketMQ 事务消息（半消息回查）、分布式 ID（雪花/Leaf）、优惠金额分摊算法（最后一行兜底差额）。

### 5.2 订单状态机
- **完整功能**：状态流转：待支付→已支付→待发货→已发货→已签收→已完成，任意前置状态可→已取消/退款中；每次流转记录状态流水（谁/何时/触发事件）；非法流转直接拒绝。
- **关键规则**：状态变更以数据库乐观锁（where status=旧状态）保证并发下不跳变。
- **技术落点**：状态机模式、乐观锁 CAS 流转、状态流水审计。

### 5.3 订单查询
- **完整功能**：买家视角：列表（分页+状态筛选）+ 详情（订单+SKU 快照+物流+支付信息）；商家视角：按店铺/时间/状态查询；三个查询维度：订单号、buyerId、sellerId 都能直接查。
- **关键规则**：分片键为 buyer_id；seller/订单号维度查询走异构索引表（订单号内嵌 buyer 基因路由）。
- **技术落点**：分库分表 16 库×64 表、基因法多维度路由、异构索引表、历史订单归档 ClickHouse。

### 5.4 取消订单与超时关单
- **完整功能**：用户主动取消（待支付状态）立即回补库存；下单 15 分钟未支付自动关单回补——延迟消息实现；关单前二次校验支付状态防「已支付却关单」竞态。
- **关键规则**：关单与支付回调并发时以「支付成功」优先，走退款流程兜底；库存回补幂等。
- **技术落点**：RocketMQ 延迟消息、竞态处理（关单 vs 支付回调）、回补幂等（唯一业务键）。

### 5.5 订单快照
- **完整功能**：下单时固化商品标题/图片/规格/单价/优惠明细到订单表；后续商品改价下架不影响历史订单展示与售后依据。
- **关键规则**：快照字段与商品中心解耦，只读不回写。
- **技术落点**：数据快照设计（反范式冗余）。

### 5.6 订单超时分级提醒
- **完整功能**：已发货超 7 天未签收自动确认（延迟消息）；确认收货触发积分发放与评价开启。
- **关键规则**：自动确认前消息/短信提醒一次。
- **技术落点**：延迟消息多场景复用。

### 5.7 订单分库分表改造
- **完整功能**：单表日增千万后迁移：双写过渡（新旧库同时写）→ 历史数据迁移对账 → 灰度切读 → 全量切写 → 停双写；迁移期间提供回滚开关。
- **关键规则**：迁移对账以 count+抽样字段比对，差异自动修复。
- **技术落点**：ShardingSphere、双写迁移方案、数据对账（面试级亮点）。

## 板块六：库存板块 [M1 起步/M2 增强]（5 个功能点）

### 6.1 库存管理
- **完整功能**：后台入库/盘点/调整库存；SKU 维度库存台账（每笔变动有流水：类型/数量/关联单号）；可售库存=实物库存-锁定库存。
- **关键规则**：台账只增不改（流水制）；调整需双人复核（超阈值）。
- **技术落点**：库存流水表设计、台账审计。

### 6.2 库存预扣（防超卖核心）
- **完整功能**：下单走 Redis Lua 脚本原子执行「查库存→判限购→扣减→记录用户」；扣减成功才发下单消息；DB 层 `UPDATE ... SET num=num-? WHERE sku_id=? AND num>=?` 乐观锁二次兜底。
- **关键规则**：Lua 脚本内完成全部判断，杜绝查了再扣的竞态；Redis 与 DB 库存允许短暂不一致，靠对账收敛。
- **技术落点**：Redis+Lua 原子扣减、DB 乐观锁兜底、两层防线防超卖。

### 6.3 库存回补
- **完整功能**：取消/超时关单/扣减后下游失败三类场景回补；回补幂等（订单号唯一键）；支持批量回补（大促后统一释放锁定库存）。
- **关键规则**：回补消息重复投递不重复加库存。
- **技术落点**：幂等消费、死信队列人工兜底。

### 6.4 库存分桶（大促热点）
- **完整功能**：超热 SKU 库存拆 N 桶（如 100 件拆 10×10），请求 hash 路由到不同桶并行扣减，单 key 热点消除；某桶售罄自动切换下一桶；全售罄后合并兜底池最后放量为 DB 直扣。
- **关键规则**：分桶数 = 预估峰值 QPS / 单 key 承受上限；桶间不平衡可再平衡。
- **技术落点**：热点 key 分片、库存分桶方案（差异化亮点）。

### 6.5 库存对账
- **完整功能**：XXL-Job 每 10 分钟比对 Redis 可售库存 vs DB 锁定+可售口径；差异超阈值告警并自动以 DB 为准修复 Redis；活动结束后全量终态对账。
- **关键规则**：对账期间暂停该 SKU 扣减（短时降级为 DB 扣减）。
- **技术落点**：缓存与 DB 最终一致、对账修复任务、降级开关。

## 板块七：支付板块 [M1 mock/M2 接入]（5 个功能点）

### 7.1 支付下单
- **完整功能**：创建支付单（支持支付宝/微信渠道，开发期 mock 渠道）；支付单与订单 1:1；生成渠道收银台参数返回前端拉起支付。
- **关键规则**：同一订单重复发起支付复用未过期支付单；金额以订单应付金额为唯一来源（前端传参不采信）。
- **技术落点**：支付单建模、金额服务端权威。

### 7.2 支付回调（幂等核心）
- **完整功能**：接收渠道异步回调 → 验签 → 校验金额 → 幂等处理（支付单号唯一索引）→ 更新支付单与订单状态 → 发支付成功事件（驱动发货/核销/清购物车）；处理失败返回非 200 让渠道重试。
- **关键规则**：回调处理与超时关单并发竞态：先查支付渠道侧真态再决策；主动查单补偿（回调丢失时定时对渠道查单）。
- **技术落点**：回调幂等、验签防篡改、查单补偿兜底（不依赖单一通知）。

### 7.3 退款
- **完整功能**：整单/按 SKU 行退款；退款校验（状态/金额上限/退款期限）；退款单流转：申请→审核→渠道退款→到账；退款成功回补库存、回滚优惠券与积分。
- **关键规则**：部分退累计金额不超实付；每 SKU 行只可退一次。
- **技术落点**：逆向流程建模、退款与回补的最终一致（本地消息表）。

### 7.4 资金对账（零资损防线）
- **完整功能**：T+1 拉取渠道账单与本地支付单逐笔比对（金额/状态）；差异分类（长款/短款/状态不一致）生成差错表；自动处理可规则化的差异，其余人工工单；对账结果大盘展示。
- **关键规则**：对账任务幂等可重跑；差错处理留痕。
- **技术落点**：T+1 对账体系、差错处理闭环（零资损讲点）。

### 7.5 支付超时与异常治理
- **完整功能**：支付单 15 分钟过期（与订单关单联动）；渠道异常（超时/降级）时支付入口熔断提示稍后再试；异常支付单监控告警。
- **关键规则**：过期支付单不可再支付，防重复扣款。
- **技术落点**：弱依赖熔断、异常监控告警。

## 板块八：营销板块 [M2]（6 个功能点）

### 8.1 优惠券
- **完整功能**：券模板创建（满减/折扣/无门槛；用范围：全场/类目/SKU）；发放（定向推送/用户领取/兑换码）；领取（库存扣减防超发，Redis 预扣+DB 兜底）；下单核销与退款回滚；过期自动作废。
- **关键规则**：单人限领 N 张；核销与订单绑定；防重复领取（用户+模板唯一索引）。
- **技术落点**：券库存防超发（同库存两层防线）、营销与订单解耦（事件驱动核销）。

### 8.2 满减/满折活动
- **完整功能**：满 X 减 Y / 满 X 件打 Z 折，支持阶梯（满100减10、满200减30）；活动时间窗管理；下单试算自动匹配最优组合。
- **关键规则**：优惠不叠加冲突（券与满减互斥规则可配）；试算与结算口径一致（防「试算价≠支付价」资损）。
- **技术落点**：最优优惠组合计算、价格中心统一口径。

### 8.3 秒杀（大促核心，完整吸收前版秒杀方案）
- **完整功能**：活动创建（商品/时间/秒杀价/限购数）→ 活动预热（提前 10 分钟库存与活动信息加载缓存+本地 Caffeine）→ 秒杀开抢：前端按钮置灰+答题打散 → 网关限流（令牌桶）+ Sentinel 热点参数限流 → Redis Lua「判限购+扣秒杀库存」→ 发事务消息 → 异步建单；库存分桶抗热点；售罄即时推送售罄标记。
- **关键规则**：秒杀库存独立于日常库存；防刷（答题/黑名单/单位置级限流）；三层防超卖同 6.2。
- **技术落点**：漏斗削峰、缓存预热、热点参数限流、库存分桶、防超卖全集。

### 8.4 营销价格试算中心
- **完整功能**：统一入口：给定 SKU 列表+用户 → 返回原价、活动价、可用券、最优组合、应付价；购物车预览/下单/支付三处共用同一试算，保证全链路价格一致。
- **关键规则**：试算结果带版本号，下单时以提交时刻试算为准，价格变更需用户重新确认。
- **技术落点**：价格一致性（防羊毛党与资损的关键设计）。

### 8.5 活动数据看板
- **完整功能**：活动维度实时统计：曝光/点击/下单/核销漏斗；秒杀场实时 GMV 与库存消耗曲线；数据入 Kafka → ClickHouse 聚合 → 大屏。
- **关键落点**：埋点流处理、ClickHouse 实时聚合。
- **技术落点**：Kafka+ClickHouse 实时数仓链路。

### 8.6 营销风控
- **完整功能**：领券/秒杀接口设备指纹+行为验证码；批量小号识别（注册时间/行为特征）；异常订单（同收货地址批量单）自动拦截复核。
- **关键规则**：拦截进人工审核池，误杀可放行。
- **技术落点**：风控规则引擎思路、异步拦截不阻塞主链路。

## 板块九：评价板块 [M3]（3 个功能点）

### 9.1 发表评价
- **完整功能**：确认收货后可评价：星级+文字+图片（≤9 张，MinIO）；评价含 SKU 维度标签（质量好/物流快）；首次评价赠积分；支持追评（一次）。
- **关键规则**：仅真实订单买家可评（订单快照校验）；敏感词过滤（DFA 算法）；图片审核（先发后审+异步机审）。
- **技术落点**：DFA 敏感词过滤、内容异步机审削峰。

### 9.2 评价展示
- **完整功能**：商品详情页评价列表（标签聚合、图片墙、追平展示）；好评率统计（定时任务聚合到商品统计表，不实时算）；评价排序（有用数/时间）。
- **关键规则**：评价存 MongoDB（schema 灵活+海量写入），聚合统计同步 MySQL 商品冗余表供列表页读。
- **技术落点**：MongoDB 场景选型、读写分离式聚合统计。

### 9.3 商家回复与申诉
- **完整功能**：商家回复评价（一条评价一次）；差评申诉流程；违规评价举报下架。
- **关键规则**：回复也走敏感词过滤。
- **技术落点**：常规 CRUD + 审核流。

## 板块十：物流板块 [M3]（3 个功能点）

### 10.1 运费模板
- **完整功能**：按区域（省市级）/件数/重量/金额维度配置运费规则；包邮条件设置；下单时按收货地址匹配模板计算运费。
- **关键规则**：多模板命中取最优（商家可设优先级）。

- **关键规则**：轨迹拉取失败重试+告警，不阻塞发货主流程。
- **技术落点**：外部依赖弱耦合、轨迹削峰异步拉取。

### 10.3 签收与自动确认
- **完整功能**：物流状态回传签收 → 订单待签收→已签收；7 天未签收自动确认（见 5.6）。

- **技术落点**：状态回传幂等处理。

## 板块十一：消息通知板块 [M2]（3 个功能点）

### 11.1 站内消息

## 板块十二：平台支撑板块 [M1 网关起/M4 完善]（9 个功能点）

### 12.1 API 网关
- **完整功能**：统一入口：路由转发、JWT 鉴权（白名单放行）、接口级限流（Redis+Lua 滑动窗口）、灰度发布路由（按用户尾号/地域）、请求日志 traceId 注入。
- **关键规则**：限流维度：全局/接口/用户三级；被限流返回统一错误码与重试建议。
- **技术落点**：Gateway 过滤器链、分布式限流、灰度路由。

### 12.2 后台管理（Admin）
- **完整功能**：RBAC 权限（角色-菜单-按钮三级）；商品/订单/用户/库存/营销/内容全管理功能入口；操作审计日志（谁在何时改了什么，改前改后值）。
- **关键规则**：敏感操作（改价/退款审核）双人复核；审计日志不可删改。
- **技术落点**：RBAC 模型、操作审计（AOP 切面统一采集）。

### 12.3 对账中心
- **完整功能**：资金对账（见 7.4）+ 库存对账（见 6.5）+ 订单状态对账（支付单/订单/物流状态闭环校验）统一管理；差错工单流转；对账大盘。
- **关键规则**：全部对账任务幂等、可重跑、可暂停。
- **技术落点**：三线对账体系（资损防线全景讲点）。

### 12.4 文件服务
- **完整功能**：图片/视频上传（Presigned URL 直传 MinIO）；图片处理（缩略图/水印，异步任务）；上传防盗链与类型白名单校验。
- **关键规则**：单文件上限与格式白名单；异步处理完回调更新状态。
- **技术落点**：直传不占应用带宽、异步任务削峰。

### 12.5 消息治理组件
- **完整功能**：统一生产者封装（事务消息/普通消息/延迟消息）；消费端幂等组件（注解+Redis setnx+唯一索引自动幂等）；死信统一告警与人工重放控制台。
- **关键规则**：重放前校验幂等键；重放操作审计。
- **技术落点**：幂等脚手架化（面试讲「怎么保证不重复消费」的工程化答案）。

### 12.6 分布式 ID 服务
- **完整功能**：统一发号服务：订单号/支付单号/券码；雪花算法（机器 id 来自 DB 分配）+ Leaf 号段双模式；号段双 buffer 预取。
- **关键规则**：时钟回拨检测：小幅等待、大幅报警切号段；ID 趋势递增不暴露业务量。
- **技术落点**：雪花 vs 号段对比、时钟回拨应对（高频考点）。

### 12.7 监控告警
- **完整功能**：Micrometer 埋点 → Prometheus → Grafana 大盘（QPS/RT/线程池/JVM/中间件指标）；关键告警（错误率、P99、MQ 堆积、Redis 内存）分级通知；SkyWalking 全链路拓扑与慢查询定位。
- **关键规则**：告警阈值分级（提醒/警告/严重），严重告警电话/值班推送。
- **技术落点**：指标体系、全链路追踪、告警分级。

### 12.8 全链路压测 [M4]
- **完整功能**：压测流量染色（header 标记 → 数据写影子表/影子库，不污染生产数据）；压测场景脚本化（浏览/加购/下单/支付混合模型）；压测报告：容量水位、瓶颈定位（SkyWalking+Grafana 联动）、扩容建议。
- **关键规则**：压测前置检查（影子表就位/告警静默/回滚预案）。
- **技术落点**：流量染色+影子表（大厂真题级亮点）。

### 12.9 异地多活设计（文档级亮点 [M4]）
- **完整功能**：输出设计文档：同城双机房双活（数据层半同步复制）→ 单元化改造（按用户维度分单元、单元封闭）→ 异地灾备；GZone/RZone/CZone 划分；单元路由与容灾切换演练方案。
- **关键规则**：本文档级交付，不实机搭建——面试讲清权衡（成本 vs RTO/RPO）即达标。
- **技术落点**：异地多活架构方法论（总监级话题，讲清思路即碾压）。
